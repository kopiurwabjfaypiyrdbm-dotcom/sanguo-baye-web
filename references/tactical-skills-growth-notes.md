# 战术计谋、天气、状态与成长规则定位

本记录依据已入库、固定提交的 MIT C 核心，约束 Alpha 战术深度实现。原版计谋资源表不在允许入库的源码子集中，因此当前计谋目录与数值明确属于可替换的现代临时规则。

## 已定位的原版结构

- `baye/fight.h` 定义五种天气：晴、阴、风、雨、冰雹；战场初始天气在 `Fight.c` 设为风，`FgtDealBout` 每个新战斗日调用 `FgtChgWeather`。
- `FightSub.c:FgtChgWeather` 使用规则随机数在五种天气中选择；`FgtCount.c:CountSklHurt` 说明技能威力会按天气、双方兵种与所在地形倍率修正。
- `baye/fight.h` 定义正常、混乱、禁咒、定身、奇门、遁甲、石阵、潜踪等战术状态；`FightSub.c:_CommonJNAction` 负责写入技能状态。
- `FgtCount.c:CountBaseAttr` 与 `FightSub.c` 的技能点计算使用当前智力、武力的整数平方根、等级和体力。Web 使用相同字段关系初始化计谋点，并保留装备后的当前属性。
- `FightSub.c:FgtGetExp` 使用 `PlcExtract` 的整数平方根、双方等级差和固定基础值计算经验；`Fight.c:FgtChkAtkEnd` 以 100 经验升级，`tactic.c:LevelUp` 和默认配置把等级上限设为 20。

## 当前 Alpha 实现

- 战斗初始为风天，每个新战斗日通过持久化战术种子确定性切换天气。
- 计谋目录是数据驱动的十项现代临时表：火计、扰乱、激励、禁咒、定身、奇门、遁甲、石阵、潜踪和劫粮。它覆盖伤兵、补兵、状态施加/清除与粮草打击四类效果。
- 计谋成功率使用施展者与目标的装备后智力差；消耗、最低智力、范围、对象和天气/地形/兵种倍率集中在 `core/tacticalBattle.ts:TACTICAL_SKILLS`，便于获得原版资源证据后整体替换。
- `compat/baye/tacticalState.ts` 集中定义八种状态、原版可定位的行动/恢复语义，以及明确为现代临时数据的六兵种移动消耗和攻击范围。
- 混乱跳过行动，禁咒禁止计谋，定身把有效移动力压为 1，奇门忽略敌方控制区；石阵按日损兵。遁甲减伤、潜踪的远距不可选取和劫粮均是为了形成可玩闭环加入的现代规则。
- 战术 AI 与玩家调用同一移动、攻击和计谋函数，并在伤害、治疗、状态、粮草、主将和战场目标之间进行确定性评分；随机失败、天气变化、状态恢复和战后俘虏共享同一确定性种子链。
- 普通攻击和成功计谋累计战斗经验；手动结果通过 `BattleResult.experienceGains` 原子写回战略人物。快速结算按双方总损失为参战武将分配抽象经验，使用同一升级函数。
- 六张随应用发布的战场均由代码定义，不含原版地图数组或图片；进攻方向与目标城索引确定部署方向和战场模板。

## 明确差异

- 原版技能名称、学习列表、消耗、范围、对象、地形/兵种/天气倍率存于未入库资源；当前十项计谋只复用已定位的状态与计算管线，不宣称目录和数值逐项一致。
- 八种状态名称、跳过/禁咒/定身/奇门、石阵每日损失八分之一兵力和每日恢复极性有 C 源码证据；Web 的状态赋予来源、遁甲减伤、潜踪选取限制与持续体验仍为现代临时设计。
- 原版移动消耗、攻击范围与地形攻防修正位于禁止入库的资源数组。仓库只保留本地证据的偏移、长度与 SHA-256；产品内的对应表是独立编写的现代替代表。
- 原版天气变化受 `batlleDisableWeatherChange` 配置开关控制；Web 当前总是启用每日确定性天气变化。
- 原版在战斗过程中立即结算经验和升级；Web 为保证战术结果原子回写，在战斗结束后统一升级，因此同一场战斗内后续行动暂不享受新等级。
- 原版部分击破分支会额外奖励经验；当前普通攻击只接入基础伤害经验，击破加成后置。
- 原版满级后仍按 100 经验回卷且受 U8 存储影响；Web 保留 100 回卷但使用安全整数，避免溢出。
- 快速战斗没有逐次攻击事件，经验按总损失平均分配，是保持快速/手动成长闭环的现代抽象。
- 原版战场编号对应地图、单挑、技能学习/装备体系和逐决策战斗 AI 尚未接入。
