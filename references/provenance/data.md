# 数据来源边界

## 数据分类

| 类型 | 例子 | 当前处理 |
|---|---|---|
| 可观察规则数据 | 兵种克制、命令消耗、字段范围 | 记录来源后重建为测试夹具 |
| 上游结构定义 | C struct、常量、字段偏移 | 可作为兼容性规格引用 |
| 游戏内容数据 | 武将、城池、剧本、道具 | 先解析和核验来源，再决定发布形式 |
| 二进制资源包 | `.lib`、存档、内置字体 | 仅保存在 `.reference/`，默认不提交 |

## 解析要求

- 每个导出表记录上游 commit、源文件、解析器版本和 SHA-256。
- 保留原始 ID 和哨兵值，不在导入阶段静默重编号。
- 原始记录、规范化记录和人为修订分层保存。
- 无法确认时期或人物身份的记录进入冲突表，不自动合并。
- 用最小、人工构造的数据夹具测试解析器；不要把完整二进制复制到测试目录。

当前 `data/source/` 中的 CSV 属于早期整理结果，需要在写入正式剧本前重新关联到固定上游版本。

当前可玩版本沿用 `data/source/tool-catalog.csv` 的 33 项道具名称和数值作为临时产品数据；城池队列与人物装备引用来自已入库时期结构，但该 CSV 本身尚未满足上面的固定上游、解析器和 SHA-256 要求。因此它不能作为“原版内容已验证”的证据，也不得据此继续导入本地 `.lib` 或来源不明资产。
