# 外交谋略对照笔记

本阶段固定事实源为 MIT 参考 `citycmd.c:AlienateDrv/CanvassDrv/CounterespiongeDrv/InduceDrv`、`citycmdc.c:*Make`、`tactic.c:ComputerTacticDiplomatism`、`baye/order.h` 与 `baye/attribute.h`。

## 固定判定

- `*Make` 都把执行武将、出发城、目标人物和 `TimeCount = 10` 写入命令；体力与金钱通过未入库的运行时资源表读取，因此当前 4 体力与 50 金都是可替换临时值。
- 离间依次比较智力差加 50、目标忠诚和性格阈值；成功使忠诚减少 4，最低为 0。
- 招揽依次比较无偏移智力差、目标忠诚和性格阈值；成功把目标移到执行者出发城、改变归属，并以第四次随机调用把忠诚设为 `40 + rand%40`。成功或失败后还会为随机对话消费一次随机数。
- 策反的三段判定与离间形状相同，但使用另一组性格阈值；成功让非君主太守自立，并使所在城市与驻城武将归属新君主。固定实现失败后消费一次随机对话数，成功时还会继续落入末尾报告而共消费两次。
- 劝降首先要求发起方城池数至少为目标势力两倍，再比较智力差加 50 和目标君主性格；不检查忠诚。成功使目标势力城池和驻城人物归入发起方，目标君主以外的不在城人物失去原归属。玩家发起时无论结果都会再消费一次报告对话随机数，AI 发起则不会。
- 固定实现中智力差先写入 `U8` 或 `U32`，低智执行者可能因无符号下溢获得反直觉优势。兼容函数保留该整数宽度和严格的 `>`/`<` 比较方向，不把它静默改成现代概率公式。

## 现代命令层

当前 Web 以可保存的 `diplomaticOrders` 承载四类谋略。执行者暂时离城并占用统一命令位置，经过一个完整月份后回报；目标身份变化、移动、失去太守资格、势力灭亡或出发城易主都会走显式成功、失败或失效闭包。

原版 `TimeCount = 10` 的时间单位以及运行时体力、金钱表不在当前许可 allowlist，且固定数组命令执行路径对时间字段的处理与旧链表分支不一致。因此“一月完成、4 体力、50 金”都是明确的可替换产品规则；随机调用位置、阈值与主要成功状态转换才标记为固定参考支持。现代 UI 不复制随机对话，但仍消费对应 RNG 步骤，避免后续共享种子漂移。

策反会创建以目标太守为君主的动态 AI 势力。Web 额外处理被策反城市的俘虏羁押、原势力失地、在途命令和太守修复，避免产生无效君主或孤儿状态。若玩家先手动任命太守，导致旧君主与非君主太守同城，当前会拒绝对该太守策反；固定实现会把城中全员一并改属，而 Web 不能因此让仍有领地的旧势力失去合法君主。劝降成功后，目标君主和仍在目标城市的武将加入接收方；仍在途的其他旧部转为中立在野，目标势力全部命令安全终止。这些是基于固定结果意图与现有状态不变量的现代原子闭包。

## 情报与反馈

玩家只能以“本回合侦察快照中的人物 ID”选择目标；旧快照和只有人数/资源、没有人物名单的旧存档报告不能锁定人物。界面展示执行者、目标、成本、耗时和影响因素，但不泄露精确成功率。AI 对玩家实施的谋略会详细报告，AI 之间的行动只给势力级摘要。

反间生成/执行函数为空壳，朝贡生成函数被注释；联盟、停战、婚姻和关系网没有进入本阶段。
