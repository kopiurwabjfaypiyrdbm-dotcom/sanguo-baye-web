# 人物与搜寻命令原版定位

本记录基于本地参考快照 `Baye/baye_c/src`，用于约束当前人物经营实现，不包含原始资源。

## 在野人物

- `cityedit.c:GetCityOutPersons` 只从城市人物队列中筛选 `Belong == 0` 的人物。因此“在野”不是脱离地图的人物，而是仍隶属于某座城市队列、尚无势力归属的人物。
- `cityedit.c:GetCityPersons` 只返回 `Belong` 与城池归属一致的人物；普通驻城名单不应显示在野人物。
- 当前领域层以 `Officer.status` 区分 `serving`、`free` 和预留的 `hidden`。时期队列中无有效势力归属的人物映射为 `free`。

## 搜寻

- `citycmdb.c:SearchMake` 选择一名本城在职武将，消耗由资源常量表定义的体力与金钱，再加入命令队列。
- `pconst.c:ConsumeThew/ConsumeMoney` 显示搜寻消耗体力 8、金钱 0。
- `citycmd.c:SearchDrv` 首先进行四分支随机：无结果、人物/道具、金钱、粮草。
- 人物分支先检查 `rand % 150 < IQ`；人物与道具由该随机值奇偶区分。无指定伯乐时，再检查 `rand % 110 < IQ`。
- 成功找到人物后会直接设置为执行者所属势力，并将忠诚设为 `70 + rand % 30`，不是独立的“发现后再登用”流程。
- 奇数人物/道具分支会从城市未发现道具队列选择候选；满足道具伯乐条件后把队列高位置位，转为已发现库存。

Web 重写保留“搜寻可能直接招募”的原版路径；若已经找到人物线索但当次劝说失败，会把该人物加入玩家已发现名单，允许后续月份单独执行登用。这是为了形成可读、可规划的人才经营循环而增加的现代化路径。

## 赏赐

- `citycmdb.c:LargessMake` 要求先选择城中道具，再选择本城人物。
- 道具成功交付后从城池删除；非君主人物忠诚固定增加 8，最高 100。
- `ConsumeThew[9]` 和 `ConsumeMoney[9]` 均为 0，赏赐本身不消耗体力或金钱，成本来自道具。
- 当前 Web 已接入城池隐藏/已发现道具库存和道具赏赐：非消耗品按原版顺序进入两个通用装备位，兵符按装备后的有效武力/智力门槛一次性改变兵种；非君主忠诚增加 8，道具从城池移除且不占用月行动。为保留旧存档的经营手段，原有 100 金“赏金”暂作为并列现代命令保留。
- 当前实现保留人物/道具奇偶分支、智力门槛、忠诚范围和消耗。原版 `SearchCondition.bole` 尚未从资源接入，因此人物分支仍按“无指定伯乐”处理，道具分支暂按无指定伯乐直接发现，属于待替换的临时差异。
- `citycmdb.c:LargessMake` 在判断道具是装备型还是消耗型之前，就要求两个装备位至少有一空。因此满两件装备时连兵符也不能使用；当前 Web 保留这条反直觉但有源码证据的容量前置条件。
- 时期人物记录中的武力/智力已经包含初始装备效果。导入层会减去两件装备的加成，保存基础属性与有序装备引用；战略估值、兵符门槛、人物显示和手动战场再从同一帮助函数计算有效属性，避免重复叠加。

## 移动与任命

- `citycmdc.c:MoveMake` 允许选择 `SearchRoad` 判定为可达的同势力城市，把距离写入 `TimeCount`，并在命令入队后让人物离开出发城；`citycmd.c:MoveDrv` 才把人物加入目标城。
- 当前固定 C 的数组队列版 `citycmd.c:PolicyExec` 会在同一月份执行并删除全部非空命令，完全不检查 `TimeCount`。递减 `TimeCount` 的代码只存在于已注释的旧链表分支。因此不能把该移植运行时描述为真实跨月执行；字段与旧代码只能证明跨月曾是设计意图。
- 固定 allowlist 中没有 `SearchRoad` 的函数体，具体距离算法尚不能声明原版一致。
- `order.h` 声明移动消耗体力 4；实际 `OrderConsumeThew` 仍按未入固定 allowlist 的运行时资源表取值，不能仅凭头文件断言最终设备数值。`citycmdc.c:MoveMake` 的兼容开关关闭时错误使用输送体力索引，开启时使用移动索引；当前产品的 4 体力因此仍标为现代临时规则。
- 当前产品从 schema 4 开始采用明确的现代修复：按排序后的己方道路最短路径调动，每段道路耗时一个月，创建时消耗 4 体力并离城，月末抵达；中途存档保留命令，目标易主时返回仍属己方的出发城或安全城。它不是对当前 C 数组队列行为的逐步复现。
- `AppointMake/AppointDrv` 在当前参考源码中被注释，城市命令菜单也没有启用任命分支。当前 Web 版的手动太守任命因此属于明确的现代化管理功能，不消耗武将行动。
