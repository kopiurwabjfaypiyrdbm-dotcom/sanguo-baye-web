# 人物与搜寻命令原版定位

本记录基于本地参考快照 `Baye/baye_c/src`，用于约束当前人物经营实现，不包含原始资源。

## 在野人物

- `cityedit.c:GetCityOutPersons` 只从城市人物队列中筛选 `Belong == 0` 的人物。因此“在野”不是脱离地图的人物，而是仍隶属于某座城市队列、尚无势力归属的人物。
- `cityedit.c:GetCityPersons` 只返回 `Belong` 与城池归属一致的人物；普通驻城名单不应显示在野人物。
- 当前领域层以 `Officer.status` 区分 `serving`、`free` 和预留的 `hidden`。时期队列中无有效势力归属的人物映射为 `free`。

## 搜寻

- `citycmdb.c:SearchMake` 选择一名本城在职武将，消耗由资源常量表定义的体力与金钱，再加入命令队列。
- `pconst.c:ConsumeThew/ConsumeMoney` 显示搜寻消耗体力 8、金钱 0。
- `citycmd.c:SearchDrv` 首先进行四分支随机：无结果、人物/道具、金钱、粮草。
- 人物分支先检查 `rand % 150 < IQ`；人物与道具由该随机值奇偶区分。无指定伯乐时，再检查 `rand % 110 < IQ`。
- 成功找到人物后会直接设置为执行者所属势力，并将忠诚设为 `70 + rand % 30`，不是独立的“发现后再登用”流程。
- 当前实现已经保留上述随机分支、智力门槛、忠诚范围和消耗。原版 `SearchCondition.bole` 与道具搜寻尚未接入，因此人物分支暂按“无指定伯乐”处理，道具分支暂记为无结果。

## 移动与任命

- `citycmdc.c:MoveMake` 允许选择可达的同势力城市，以 `SearchRoad` 距离写入命令耗时；`citycmd.c:MoveDrv` 在命令完成后把人物加入目标城。
- 原版常量表中移动的体力和金钱消耗均为 0；移植版保留过一个错误地使用输送体力消耗的兼容分支。
- 当前产品规则先实现“相邻己方城市、立即到达、占用本月行动”，以后接入命令队列时再替换为按道路距离延迟完成。
- `AppointMake/AppointDrv` 在当前参考源码中被注释，城市命令菜单也没有启用任命分支。当前 Web 版的手动太守任命因此属于明确的现代化管理功能，不消耗武将行动。
