# 城市事件与月度顺序对照笔记

本阶段事实源为固定 MIT 参考 `infdeal.c:CitiesUpDataDate/RandEvents/EventStateDeal` 与 `tactic.c:ConditionUpdate`。

## 固定顺序

固定主循环先执行命令队列，再由 `ConditionUpdate` 推进月份与年份、执行年度道具/人物更新，随后依次调用城市发展、灾害状态损失和随机事件。当前 Web 保持“日历推进 → 跨月命令 → 年度人物/道具更新 → 城市生产/体力/军粮 → 旧状态损失 → 状态恢复或新事件”的状态流水线；虽然 Web 在进入结算对象时先写入新日历，但随机数消费仍保持“到期命令在先、年度随机登场在后”，年度更新也仍位于城市发展之前。

## 年度人物更新

固定 `PersonUpDatadate` 在月份为 1 且未禁用年龄增长时，将全部 200 个人物的年龄各增加 1；不区分在职、在野、未登场、俘虏或在途。Web 在每次 12 月跨入次年 1 月时对全部人物执行一次相同增长，非 1 月不增长。本阶段不因年龄删除人物，死亡和继承仍由后续生命周期阶段负责。

固定人物出现年龄为 `attribute.h:PERSON_APPEAR_AGE = 16`；真实出生年和出现城市来自 `GENERAL_CON` 的 3 字节原设备 `SearchCondition`。Web 只在既有时期人物记录上保留“晚于剧本起年”的稀疏登场年/城市字段：四时期原始稀疏计数分别为 30、15、16、8 条，不保存完整条件表或指定伯乐字段。时期 2–4 中共有 18 条记录虽满足该条件但已经出现在城市队列；队列作为当前状态事实源，不会把这些人物重新排期，因此实际隐藏日程为 30、8、10、3 条。登场年使用严格相等；城市 0 消费一次确定性随机数，其余 1–38 规范化为 0–37。人物先随全员增长，再在成功登场时重置为 16 岁。

固定 C 在载入时期时保留人物记录里的 `Belong/Devotion`，并把全部人物兵力初始化为 100；年度登场只加入城市队列，不清归属、忠诚或兵力。Web 现有状态模型则把未入队者统一建模为无所属 `hidden`，登场后转为该城可搜索的中立 `free`，保留忠诚但以 0 兵进入。这是为了让“未登场 → 在野 → 登用”形成统一、可验证产品闭环的现代规则；当前只把登场年、城市、随机调用位置和 16 岁重置标为兼容，不宣称复刻了原版登场归属与 100 兵初始化。

道具出现条件来自 `GOODS_CON`。锁定四时期的 33 项道具出生年均为 144，早于所有剧本起年，因而没有需要保留的未来道具日程；初始位置继续以时期 `GOODS_QUEUE` 为准。核心仍支持带年份和城市的稀疏道具日程，并以合成状态覆盖年度加入隐藏库存与重复拒绝，未臆造四时期中不存在的新道具。

当前 `Item.id` 表示道具类型而不是全局唯一实体；时期 4 的原始人物记录中，华佗和管辂会同时装备同一 `item-24` 类型。因此校验不能把同类型的多处引用一概当作损坏存档。年度更新会在该类型已经位于任一城市或人物装备中时拒绝再次生成；未来日程也不能提前出现在任何位置。到期类型可能因兵符使用而合法离开全部库存，所以“已到年份但无引用”不能单独判定存档损坏。若后续玩法需要逐件缴获或消耗，应先把库存迁移为独立实例 ID，再增加全局实例唯一约束。

阶段前的 schema 4 原版时期存档没有稀疏登场字段。载入时会以同一内置时期为基线，仅在整层日程字段完全缺失时迁移；部分缺失、“有城市、无年份”，或任一年份/固定城市与基线不符都会作为损坏存档拒绝，避免把当前存档误作旧层而重复增龄或改变随机调用。迁移会为全部基线排期人物补回日程元数据；其中仍是 `hidden` 的人物在未来年份保留日程，已到或已过年份则立即转为在野、年龄按 16 加已过年份计算，已经在职、在野、被俘或在途者只补元数据而不覆盖身份与归属。检测到旧日程层时，全体人物按“当前年－剧本起年”补计年龄；字段回填完成后重复载入不再增长。随机城补登场按人物源 ID 顺序消费现有确定性种子，并写入迁移日志；人物装备等既有状态不会被覆盖。

城市发展在 3、6、9、12 月为每座有归属城市消费一次随机数，使防灾减少 1–4（仅在原值大于减少量时生效）。旧旱灾/水灾会先使驻城武将兵力减少四分之一，暴动减半，再按调整后兵力计算军粮；军粮不足会再减半受供养部队并转为饥荒。

固定 C 使用严格 `food > upkeep` 才算供粮成功，因此零粮且零粮耗的城市也会进入饥荒；季度防灾也只在原值严格大于 1–4 衰减量时扣减，低值可能停留。这两项看似反直觉但目前按固定比较方向保留。

## 状态与损失

- 饥荒：商业、民忠和农业约减少 5%，后备兵减半，人口减少 25%。
- 旱灾：粮草和农业约减少 5%，后备兵与人口减少 25%。
- 水灾：粮草/农业约减少 5%，商业/金钱减少 10%，后备兵与人口减少 25%。
- 暴动：粮草/商业/金钱/农业约减少 5%，民忠减少 10%，后备兵减半。

正常城市以 `rand%100 > 防灾` 进入事件候选，再以 `rand%5` 选择旱灾、水灾、暴动或无事件；暴动另要求 `rand%100 > 民忠`。饥荒在有粮时恢复；旱灾/水灾以 `rand%100 < 防灾` 恢复；暴动以 `rand%100 < 民忠` 恢复。新生成灾害在下一次月结算才承受状态损失。

## 现代边界

- 在途武将沿用 v0.4 的现代供养城市规则；灾害兵力损失只作用于实际驻城武将，粮荒则会影响该城供养的驻军与在途部队。
- `City.condition` 缺省为 `normal`，因此 schema 4 旧存档无需复制或迁移原版二进制字段。
- 事件只向玩家详细报告己方城市；AI 灾害治理使用不含城市名的势力摘要，避免绕过侦察泄露敌城实时状态。
- 治理立即恢复正常并提升防灾；固定运行时成本表仍缺失，50 金和 4 体力保持 provisional。
