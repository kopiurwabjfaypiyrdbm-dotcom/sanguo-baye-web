# Mission Brief: 手动战术具有接近原版结构的完整深度

## Outcome

手动进攻与防守不再依赖两张临时地图、三项计谋和少量状态；战场部署、地形移动、攻击范围、技能、天气、状态、粮草、战斗日、目标条件和 AI 形成数据驱动且有证据边界的完整战术游戏，同时使用来源明确的现代地图与表现，结果可靠回写战略战役。

## Context

- 当前战术已支持六兵种、每方最多十将、移动、普通攻击、五天气、火计/扰乱/激励、混乱、经验成长、装备属性、粮草、攻守 AI、快速结算与手动结果原子回写；真实能力与缺口见 `docs/HANDOFF.md` 和 `references/parity-matrix.md`。
- `references/vendor/baye-c-core/src/baye/fight.h`、`Fight.c`、`FightSub.c`、`FgtCount.c`、`FgtPkAi.c` 与 `citycmdd.c` 是战术结构和规则第一事实源；原版地图、技能与范围资源不在已批准 vendor allowlist。
- 固定参考明确存在八类地形、五种天气、多个战术状态、数据驱动技能效果和范围、城市战场编号与进攻方向；单挑命令在固定版本中被注释，不能未经证据变成硬需求。
- 本阶段应建立在前序战略命令、事件、外交和生命周期的稳定状态闭包上，尤其复用死亡政策、装备唯一性、在途命令、俘虏和君主处理。

## Required Behaviors

- 战场模板、部署、目标格、进攻方向、地形和单位初始位置由可替换的数据定义；四时期和不同城市不再反复落入两种同质布局。
- 六兵种、装备、八类地形、移动阻力与攻击范围通过证据支持的兼容表或明确的现代替代表驱动；路径、可达格、攻击预览和实际结算一致。
- 技能支持数据化目标、范围、技能点、兵力与粮草变化、天气、地形、兵种倍率和状态效果；至少覆盖固定参考中正常、混乱、禁咒、定身、奇门、遁甲、石阵、潜踪与死亡政策相关语义。
- 战斗日、攻守阶段、粮草消耗、主将或关键单位败退、占城、全灭、粮尽和期限结束都有明确且可验证的胜因；快速与手动结果遵循同一战略回写不变量。
- 战术 AI 能根据目标、粮草紧迫度、可达位置、攻击/技能收益、状态、主将安全和攻守职责作出确定行动，不依赖 UI 或不可重放计时。
- 战术会话在刷新、保存和 AI 守城检查点上的恢复政策清晰；任何结果只能应用一次，陈旧结果与已变化战略状态被拒绝。
- UI 清楚展示当前方、可行动单位、路径成本、预计伤害、技能合法性、状态、天气、粮草、战斗日、目标和胜因；反复进入战场不泄漏 Phaser 场景、监听器或持续 CPU。
- 战后经验、死亡、俘虏、装备和城市归属使用前序核心生命周期规则原子结算。

## Constraints

- 不提交原版地图数组、图片、字体、技能资源、`.lib`、WASM、生成的内嵌资源或 GPL 离线实现；本地原版资料只用于只读比较和最小不可替代夹具。
- 产品战场使用原创、程序化或许可证明确的结构化地图；机械兼容与表现资产分离，不能因地图许可阻塞战术深度。
- 只有源码定位加可重复参考输出支持的规则进入兼容层或获得“原版一致”声明；其余保持命名清楚、可替换的现代规则。
- React/Phaser 只呈现和收集操作，战术合法性、路径、伤害、技能、AI、胜负和战略回写由核心负责。
- 以可玩的纵向增量推进；每个稳定增量运行相关测试，阶段检查点运行 `npm run check`、浏览器攻防验收，并经过战术规则、状态/存档、UI/性能、证据/许可证中至少三个独立只读审查视角和修复闭环。
- 不推送、不发布、不执行外部写入、系统级安装或破坏性操作。

## Non-goals

- 不要求逐像素、逐帧、逐动画或逐 BBK 随机序列复刻。
- 固定版本中注释掉的单挑不是完成门槛，除非后续证据表明目标原版实际启用且用户扩展范围。
- 不在本阶段完成正式全量武将头像、音乐、音效、云存档、多人联机或 MOD 平台。

## Evidence of Completion

- `npm run check` 通过；路径与范围表、技能效果、各状态、天气、粮草、战斗日、全部胜因、AI、战略守卫、迁移或恢复政策具有自动化覆盖。
- 通过许可允许的 C oracle、合成夹具或可重复本地比较验证代表性兵种、地形、装备、技能与部署结论；每项兼容声明可追溯。
- 浏览器分别完成一场玩家进攻和一场玩家防守，实际使用移动、普通攻击、多个技能/状态、天气变化与不同胜因，并在战后核对经验、人物、装备、俘虏和城市归属；控制台无应用错误。
- 四时期长期战役同时覆盖快速与手动战斗，不因战术状态、死亡、连续守城、保存重载或 AI 行为卡死。
- 重复进入和退出战场不会增加开发服务器、遗留场景/监听器或产生明显持续 CPU 异常；生产包体警告有明确风险判断。
- 至少三个独立只读审查视角完成，所有 P0/P1 和本阶段引入的 P2 已修复或有可信非阻塞说明。
- README、交接、一致性矩阵和来源记录准确区分兼容机械、现代地图、已知有意变化和仍未验证的原版资源。

## Delegated Decisions and Unknowns

- 执行者可按玩家价值和证据可得性选择先扩展路径/范围、技能/状态、目标/粮草或 AI；优先保持现有手动战斗始终可玩，不以大爆炸重写替代增量。
- 原版资源表只能本地读取时，可提取最小、不可替代的行为夹具或统计结论；若某数据可能构成受限资源再分发，应使用原创替代并记录，不提交原表。
- 战术会话是否需要完整战中存档、仅重启战前检查点或版本化折中由执行者依据恢复体验、实现风险与现有存档合同决定。
- 原版立即占城与当前阶段确认等有意差异可保留为版本化规则选项或现代默认，只要界面清楚且证据记录完整。

## Autonomy and Approval Boundaries

- 可自主修改本仓库、只读研究固定与本地参考、运行测试/构建/oracle/长期推演、复用单个本地开发服务器、执行浏览器验收、更新文档、创建本地检查点提交，并派发只读子智能体审查。
- 可自行修复战术、战略回写、性能、UI、测试和证据问题，只要不越过资产与兼容边界。
- 采用第三方或原版资产、外部发布/写入、系统级安装、产生费用、不可逆操作或扩大到单挑/正式全量美术时必须请求用户确认。
