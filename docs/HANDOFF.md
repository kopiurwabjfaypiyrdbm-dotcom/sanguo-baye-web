# 项目交接：sanguo-baye-web

更新日期：2026-07-26

## 1. 项目目标

本项目是对步步高电子词典版《三国霸业》的现代 Web 重写，不是给现有 WASM 移植版重新套一层界面。

长期方向是：以固定版本的 C 移植核心和可重复运行结果为规则事实源，在 TypeScript 中逐步重写规则层；用 React 与 Phaser 提供现代化、可维护的表现；在不分发来源不明原版资产的前提下，最终形成完整可玩的游戏。

现阶段的决策原则是“产品进度优先、在实现过程中验证原版”。技术底座已经能够支持持续开发，不应重新回到长时间只研究、不增加可玩内容的状态。

## 2. 当前玩家可体验的内容

应用已经形成可连续游玩的战略层闭环：

- 标题屏支持“新君登基”和从自动存档“重返沙场”。
- 可选择董卓弄权、曹操崛起、赤壁之战、三国鼎立四个时期，再选择君主开始战役。
- 四个时期均使用随应用发布的结构化数据，可进入 38 城完整战略地图，不需要玩家选择本地 `.lib` 文件。
- 地图支持拖动、缩放、城市选择和势力颜色反馈。
- 玩家可执行开垦、招商、治理、出巡、交易、宴请、掠夺、征兵、兵力分配、搜寻、登用、赏金、道具赏赐与装备管理、侦察、战后招降/释放、道路调动、资源输送、太守任命和出征。
- 道路调动与资源输送会跨月执行并进入 schema 4 存档；在途武将保持唯一归属，目标易主、势力失地和抵达失败均有确定性闭包。固定 C 当前数组命令执行路径忽略 `TimeCount`，所以“排序 BFS、每段道路 1 个月”是有证据动机的现代修复，不声明现行原版运行时一致。
- 交易保留 5 金买 1 粮、1 粮卖 2 金的固定比率；宴请恢复 50 体力并为非君主增加 1 忠诚；掠夺将民忠、农业、商业折半并按有效智武获得资源。30,000 软上限、防暗损、临时成本和危险二次确认属于现代安全或 provisional 产品规则。
- 月末会执行战略 AI、资源结算、体力恢复、年月推进、胜负判定和事件摘要。
- 城池会持久处于正常、饥荒、旱灾、水灾或暴动；旧状态损失、季度防灾衰减、恢复判定、治理清除与 AI 应对均走核心规则。
- 跨入 1 月时全部人物年龄增长；四时期生成数据保存 69 条稀疏未来条件，城市队列优先后形成 51 条实际隐藏日程。到期人物按固定城或一次确定性随机城进入可搜索在野，年龄重置为 16；阶段前 schema 4 存档会幂等回填及补登场。
- 支持自动存档、3 个本地手动槽、JSON 导入和导出。
- 相同状态、命令和随机种子会产生相同结果。
- 玩家出征可选择快速结算或进入 Phaser 手动战场，完成移动、普通攻击、待命、敌方基础 AI 和胜负结算后返回战略地图。
- AI 进攻玩家城市时会暂停月度推演，让玩家手动守城；战斗结束后从下一 AI 势力继续推演。
- 战术 v0.8 已加入按进攻方向部署、六张代码定义战场、原版六兵种基础移动力、八状态、五天气、十项现代计谋、控制区、主将、粮草/天数胜负、完整预览与确定性评分 AI。
- 战略节奏已把所有在职势力对称设为 400 开局兵力，取消玩家 100/AI 800 的旧临时不对称；同时增加公平的单次增兵上限，并提高开局月 AI 出征阈值。
- 兵力分配会消耗武将当月行动，不能通过重复分配绕过单次上限；势力失去最后一城后，其全部在职武将转为无所属在野，避免残留在敌方城市。
- 手动战场当前每方最多部署 10 名武将；战斗相关人物数值在状态入口要求有限、非负整数，避免非法存档进入兼容公式后崩溃。
- 手动战场已有五天气、八种状态和十项数据驱动现代计谋；普通攻击与计谋累积经验，快速/手动战后共用 100 经验升级和 20 级上限回写。
- 四时期的 33 项临时道具目录、隐藏/已发现城池库存和人物初始双槽装备已经进入状态；搜寻可发现道具，赏赐可装备物品或消耗兵符改变兵种，AI 也会使用已发现道具，装备有效属性进入战略与手动战斗。目录内容来自仓库早期整理表，重新关联固定上游前不宣称原版内容一致。
- 快速与手动战斗共用确定性战败俘虏回写；俘虏保存原所属、羁押势力和城市，玩家可招降或释放，战略 AI 会优先尝试招降低忠诚俘虏。
- 敌城详情默认遮蔽；玩家可从己城派武将侦察任意非己方城市，取得带年月的资源、城防与驻军汇总快照。原版头文件声明侦察消耗 4 体力，但运行时体力与金钱都来自未入库资源表；当前 4 体力、50 金和持久化快照均按可替换临时规则管理。
- 玩家取得本月人物名单后，可由另一名待命武将发起离间、招揽、策反或劝降；命令按临时产品规则消耗 4 体力、50 金并跨月回报。四项判定已按固定 C 的随机调用、整数宽度、忠诚与性格比较重写，目标移动或身份变化会安全失效；策反可建立新势力，劝降会原子处理城池、驻将、俘虏与在途命令。AI 会在有限行动预算内使用相同核心命令，玩家结果优先进入月报。
- 人物生命周期已进入 schema 5。新战役可在君主选择屏锁定战败死亡、自然死亡和俘虏逃脱政策；安全默认仅保留年度年龄增长，三项风险政策关闭。处斩、流放和没收均由核心原子操作处理，死亡会回收装备、取消关联命令并修复太守。
- 玩家君主被俘或死亡且仍有继承候选时进入可保存的强制继承阶段；城池命令、月末和 AI 推进冻结，但保存、导出和返回标题仍可用。AI 按稳定属性顺序自动继承；无人可继时势力瓦解，玩家势力结束战役。
- 道具现在按唯一实例校验。同一种目录道具可以有多个稳定实例 ID，但任何实例不能同时出现在人物装备、城市库存或隐藏库存；schema 1–4 会迁移历史重复，schema 5 的重复损坏会拒绝载入。
- 自动化基线既覆盖四时期最长 48 个月的完整 AI 推演（允许战役提前合法结束），也用不发生终局的结算夹具逐时期完整推进 48 次、经历 4 次年度更新，并比较每 6 个月重载与不中断结果；一城弱势君主最长 48 个月双跑保持确定。

内置 12 城示例状态仍作为测试夹具保留；正式开局流程默认使用四时期完整剧本。

## 3. 当前尚未完成的关键内容

手动战术战斗 v0.8 已形成完整 Alpha 纵向闭环，但距离逐结果还原原版仍有差距。当前战场使用来源明确的现代结构化地图和确定性评分 AI，已接入原版基础移动力、五天气、八状态语义、十项现代计谋、控制区、主将、粮草/天数胜负和经验成长；尚未接入原版战场编号对应地图、资源内精确移动/攻击表、原版技能目录/学习条件、单挑和逐决策战斗 AI。

其他主要缺口：

- 城市命令、月度结算和战略 AI 中仍有现代临时公式，不能声明为原版一致。
- 原版命令队列意图已经通过可保存的现代跨月道路命令落地，但固定 C 当前执行路径、道路算法和准确耗时仍未形成逐结果一致证据；人物登场的年、城、随机位置与 16 岁重置已接入，登场后统一转中立在野和 0 兵是明确现代规则。
- 道具基础闭环已形成，并已切换为原版顺序的两个通用装备位；道具伯乐条件、战后缴获、更完整的 AI 配装以及 33 项目录内容的固定来源重关联仍待接入。
- 原版技能目录、原版地形地图和原版战斗 AI 尚未完成；当前十项计谋、六张地图、移动/攻击范围表和 AI 权重是可替换现代规则。八状态的名称与部分行为已按固定 C 接入，其中石阵每日损失八分之一兵力已有源码证据；遁甲减伤和潜踪选取仍是现代设计。俘虏处置、可选战死、装备回收和君主继承闭环已完成，但 BBK 设备默认死亡开关、月度逃脱、自然死亡与完整人物关系仍未还原。
- 反间、朝贡、联盟、婚姻、人物关系、时期剧情及更完整的历史演进尚未实现；固定参考中的反间为空壳、朝贡被注释，当前不把菜单名称误当成已证实玩法。
- 当前视觉是现代化信息原型，尚未进入正式美术生产和移动端专项适配。

准确的原版兼容状态以 `references/parity-matrix.md` 为准。README 中的功能描述是玩家能力摘要，不能替代一致性证据。

## 4. 建议的接手重点

v0.4–v0.8 的 Alpha Mission 已完成到战术纵深阶段。下一阶段应从真实试玩问题出发，优先处理战役节奏、战术数值平衡、界面可读性和包体拆分；只有在出现可再分发证据时，才把现代战术表替换为原版资源值。

原版地图资源许可边界未解决前，继续使用来源明确、可替换的结构化战场，不得提交原版地图数组、内嵌资源或图片。人物生命周期的新死亡/俘虏结果必须继续通过 `core/officerLifecycle.ts` 原子回写，战术层不得直接拼装死亡与继承状态。

## 5. 技术结构

```text
src/core/          战略领域状态、命令、AI、经济、战斗、回合、存档和校验
src/compat/baye/   有独立参考输出支持的原版兼容算法
src/data/          四时期数据、CSV/JSON 与原版资源解析转换
src/game/          Phaser 场景、战略地图和 React/Phaser 事件桥
src/ui/            React 开局流程、城池面板和应用编排
references/        上游锁定、来源边界、一致性矩阵、夹具和研究记录
data/source/       可编辑的数据整理表
docs/design/       已确认的设计和兼容策略
```

重要边界：

- `src/core/` 负责规则和状态变更，UI 不复制合法性判断或数值公式。
- `src/compat/baye/` 只保存经过原版源码或独立输出支持的兼容实现。
- React 管理应用流程和面板，Phaser 管理画布场景；两者通过显式事件和状态更新通信。
- 规则函数延续不可变状态更新，并在完整操作后执行状态校验。
- `GameState.rngSeed` 是确定性推演的一部分，新增随机行为必须保存并推进种子。

## 7. 本地运行与验证

环境要求：Node.js 20 或更高版本。

首次拉取或依赖锁变化后：

```bash
npm ci
npm run check
```

日常开发：

```bash
npm run dev
```

`npm run check` 是一次性验证命令，不是常驻服务。它会依次验证已入库参考源码的提交与哈希、并行运行 Vitest，并执行 TypeScript 和 Vite 生产构建；短暂使用多个 CPU 核心属于正常现象，完成后所有测试工作进程应退出。当前交接基线为 337 项测试通过、4 项需要额外本地原版资料的条件测试跳过，51 个锁定 C 参考文件校验和生产构建通过。

只能保留一个 `npm run dev`。Vite 开发服务器会持续监视仓库文件，应在原终端按 `Ctrl+C` 关闭。项目启用了严格端口检查；若端口占用，应复用或关闭原实例，不要改用连续的新端口启动多个服务器。

Vite 当前会提示主 JavaScript 包超过 500 kB；这是已知的非阻塞警告。引入新的大型战场模块时应考虑按场景动态加载，但不要在战术闭环之前展开无目标的性能重构。

## 8. 原版参考资料和许可证边界

日常需要的 51 个 MIT C 规则与结构源码已经入库：

```text
references/vendor/baye-c-core/
```

它们绑定 `references/upstream-lock.json` 中的固定提交，并由 `MANIFEST.json` 保存逐文件哈希。普通开发不需要初始化额外参考。

只有更新 vendored 基线时才顺序执行：

```bash
npm run reference:setup
npm run reference:sync-core
npm run reference:check
```

仅研究额外资料时，从下列级别选择一个，不能顺序执行：

```bash
npm run reference:setup          # 少量补充参考
npm run reference:setup:full     # 完整 C 工程和技术文档
npm run reference:setup:offline  # 完整参考再加 GPL 离线运行壳
```

这些互斥命令把资料放到被 Git 忽略的 `.reference/`。`reference:setup:offline` 会显式获取 GPL 离线运行壳，只能作为本地参考。

禁止提交或混入正式产品的内容包括：`dat.lib.orig`、其他 `.lib`、字体、原版图片、音视频、WASM、内嵌原版资源数组，以及未确认独立再分发许可证的技术文档。四时期 `baye-periods.json` 是已解析的结构化运行数据，不包含上述原始文件。

## 9. 存档与兼容注意事项

- 当前 `GameState.schemaVersion` 为 5，存档通过版本化 envelope 管理；旧 schema 会逐级迁移并补入情报、战略/外交命令、生命周期安全政策和唯一道具实例层。
- schema 5 保存人物死亡记录、生命周期政策和待决继承。待决继承是可恢复玩法状态，不得降格为 React 临时状态；AI 守城流程中的继承还要保存恢复势力游标。
- 外交命令层也是 schema 4 的兼容扩展；旧存档整层缺失时迁移为空命令表并从序号 1 开始。情报快照可保存当时观察到的人物 ID，旧快照没有名单时仍可查看汇总，但不能据此锁定外交目标。
- 年度登场字段是 schema 4 的可选兼容扩展；载入旧时期战役时，仅当整层字段完全缺失才从同一内置时期迁移，并为全员补计旧版本遗漏的年度年龄。已有完整层必须逐条匹配内置年份与固定城市，部分缺失或被改写会拒绝载入；迁移不覆盖已在职、在野、被俘或在途人物的身份和归属。
- 修改 `GameState` 的持久字段时，必须同时处理序列化、解析、迁移、完整性校验和测试。
- 应用在战略状态更新后覆盖自动存档。AI 进攻玩家时，`saveStorage.ts` 另保存战前战略检查点、待执行攻击和 AI 恢复游标；连续守城之间会覆盖为新的检查点。
- 当前不支持精确战中存档。玩家进攻与 AI 守城都在战前写入恢复日志，刷新后确定性重开该战斗；战术局面不会被序列化。结果通过战斗 ID、完整战略指纹与两阶段提交原子写回，已提交但尚未清理的日志会优先恢复到战后状态。
- 战斗结果只能应用一次，并应拒绝随机种子、回合或城池归属已经变化的陈旧结果。

## 10. 已知易踩点

- `executeAttack()` 当前直接完成战斗并修改战略状态；接入手动战场时应拆分“验证并创建战斗”与“完成后应用结果”，不要在 UI 复制现有校验。
- 自动存档由 React 状态更新触发。新增短暂 UI 状态不必进入 `GameState`，但影响可恢复玩法的状态必须有明确持久化策略。
- 原版时期人物包含在职、在野和未登场状态；不能假设每个人都有势力或城市。
- 中立城市使用非玩家中立势力桶，不获得普通 AI 回合。
- Phaser 战略地图由 React 创建一次，再通过 controller 更新。新增战场场景时需要明确场景销毁和返回地图的生命周期。
- 上游存在 Windows 保留文件名 `con.py`；参考初始化脚本已经通过安全落盘规避，不要恢复为直接稀疏检出整个工作树。
- “测试通过”不等于“原版一致”。一致性状态必须同时有源码定位或可重复参考输出。
