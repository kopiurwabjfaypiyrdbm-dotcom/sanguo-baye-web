## 2026-08-02：城池命令默认执行者与库存反馈

### 已完成

- 打开具体城池命令时，默认执行者会优先选择尚未行动、体力达到该命令要求且身份合法的武将；奖赏、宴请、太守和流放等目标型命令也会避开显然无效的人选。
- 没有完全可执行人选时，优先回退到尚未行动的驻城武将，再回退到原始驻城顺序；用户手动改选后不会被自动选择逻辑覆盖。
- 命令摘要中的金钱、粮草、后备兵和体力统一显示为“本次消耗 / 当前库存”，例如“金钱 50 / 城中 187”“体力 8 / 马玩 100”；原有红色禁用原因继续解释资源不足或其他阻塞。
- 城池节点一级快捷菜单补充城中金钱，与粮草和总兵力并列，常用基础状态不再必须进入详情页查看。
- 本轮只调整默认选择和信息呈现，没有改动命令规则、成本、随机数、存档或 AI。

### 验证状态

- 浏览器实测同一存档中马腾已行动、马玩待命：开垦和招商均默认选中马玩，命令按钮直接可用，库存数字与天水实际状态一致。
- 手动改选杨秋后选择保持稳定，收益范围与体力库存同步刷新；返回一级菜单可见“金 187 · 粮 505 · 兵 800”。
- `npm run check` 通过：51 个固定 C 参考文件校验、358 项测试通过、4 项本地参考测试跳过，TypeScript、Vite 与 PWA 构建成功。

## 2026-08-02：移动端单层城池命令编辑器

### 已完成

- 保留“城市节点 → 分类 → 具体命令”的地图锚定层级；具体命令改为单一聚焦编辑器，普通命令在同层展示执行者、参数、预期效果、成本、行动消耗和禁用原因后直接提交，不再打开通用复核弹窗。

- 21 个现有城池命令仍由原有核心回调执行；本轮没有修改规则、成本、随机数、存档或日志路径。
