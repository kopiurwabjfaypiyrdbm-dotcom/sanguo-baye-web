# 现代 Web 存档

当前存档目标是稳定承载 Web 重写的长期战役，不尝试伪装成原版设备存档。

## 格式

- 外层 `SaveEnvelope` 使用 `format: "sanguo-baye-web"` 与独立版本号。
- 内层保存完整、已经解析的 `GameState`，包括日历、阶段、人物、城池、日志、行动名单和随机种子。
- 不保存或复制原始 `dat.lib.orig`；剧本来源只记录为已经解析的时期标识。
- `GameState` 当前结构版本为 5；载入器支持把 schema 1–4 迁移到当前结构，并拒绝 schema 5 中的重复道具实例等损坏状态。
- 所有载入结果必须通过完整状态校验后才能进入游戏。

## 浏览器行为

- 战役开始后，每次状态更新都会覆盖自动存档。
- 提供 3 个手动槽位，覆盖已有槽位前需要确认。
- JSON 导出用于备份或跨浏览器转移；JSON 导入走同一迁移和校验流程。
- 若自动存档损坏，应用回退到内置剧本，避免阻止启动。

## 手动战斗恢复

- 战术会话不写入普通 `GameState`，因此普通存档始终停留在可校验的战略边界。
- 进入玩家进攻或 AI 守城前，浏览器写入版本 2 的 `BattleRecoveryJournal`，保存完整战前战略状态、命令、确定性种子位置和 AI 恢复游标。
- 刷新不会恢复到战中某一格，而是从同一战前状态确定性重开战斗；界面会明确提示“战斗已重新开始”。
- 战斗结果写回时同时核对战斗 ID、回合、种子、目标归属和不含日志的完整战略指纹。陈旧、重复或与战前状态不一致的结果会被拒绝。
- 写回采用 `pending → committed → 自动存档 → 删除恢复日志` 的两阶段流程。若浏览器在写入窗口中崩溃，下一次“重返沙场”以已提交状态为准，不会再次应用同一战果。

原版存档格式的研究属于兼容层工作，未来即使支持导入，也应转换为现代 `GameState`，不与本格式共用版本号。
