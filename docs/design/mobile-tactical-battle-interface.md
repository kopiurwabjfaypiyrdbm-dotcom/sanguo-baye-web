# 移动端战术战斗界面交付说明

本阶段把手动战斗收敛为独立的全屏横屏模式。战场始终占据主要视觉空间，当前决策使用底部动作栏完成，编队、敌军、战况和日志通过边缘面板按需展开。战斗规则、确定性随机序列、恢复检查点和战略回写均未改变。

## 布局约定

- 顶栏只保留战场名称、日期、行动方、双方总兵力、天气和未行动队伍数。
- 地图铺满顶栏与底部动作栏之间的区域，不常驻遮挡可玩格子的详情面板。
- 底栏固定显示当前单位，以及移动、普攻、计谋、待命、结束阶段和撤退六类操作。
- 我军、敌军、战况和日志使用边缘面板；短横屏下编队使用双列滚动列表，关闭后立即归还地图空间。
- 精确移动格、攻击目标和计谋目标只在相应动作被选择后出现，并显示成本、预计伤害、成功率或不可用原因。
- 攻击和撤退都经过显式确认；攻击预览可以取消并重新选动作或目标。
- 战斗结束后只保留结算返回战略地图的主操作，防止重复写回。

## 触控与桌面输入

- Phaser 画布捕获触摸输入，浏览器页面不会抢走战场拖动手势。
- 单指在空白战场拖动可平移镜头；按下到抬起移动超过 10px 时认定为拖动，不触发格子选择。
- 轻触单位或格子仍通过既有 React–Phaser 桥接状态执行选择和动作，键盘与桌面鼠标继续可用。
- 小横屏关键按钮高度至少为 44px；页面本身固定为 `100dvh`，滚动只发生在主动打开的面板内部。
- 竖屏保留可操作的降级布局，但本阶段验收目标为手机横屏。

## 规则与恢复边界

- 权威移动、攻击、计谋、状态、AI 和胜负判定仍由 `src/core/tacticalBattle.ts` 提供。
- UI 只展示权威状态和提交既有动作，不另行计算随机结果。
- 刷新后从战前检查点重建同一场进攻；完成结算后只向战略层写回一次。
- 本阶段没有新增战术单位、技能、地图、AI 行为或原版兼容性声明，也没有引入来源不明资产。
