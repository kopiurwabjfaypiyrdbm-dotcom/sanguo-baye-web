# 移动端视觉与设备验收记录

本记录对应 `docs/mission-briefs/mobile-visual-polish-and-device-acceptance.md`。当前交付将手机横屏视为首要浏览器形态，同时保留平板和桌面布局。下列移动设备结果来自 Codex 内置 Chromium 的 CSS 视口模拟，不代表真实 iOS Safari 或 Android Chrome 真机认证。

## 视觉与交互基线

- 深青沙盘、米色阅读面板、暖金主操作和克制的红色危险操作贯穿标题、战略、目录、命令确认、月报和战术界面。
- 选中态同时使用边框、背景、文字或 `aria-pressed`，未知情报、禁用原因、危险操作和已完成状态均有文字标签，不依赖颜色单独传达。
- 成功与错误反馈新增 `✓` / `!` 非颜色标记；高对比度偏好会加强边框与选中轮廓。
- 抽屉和确认面板使用 140–200ms 的短过渡；`prefers-reduced-motion: reduce` 会把动画和过渡压缩到近乎即时。
- 字体只使用系统字体栈，不下载或打包原版字体。界面图形由 CSS、Phaser 几何图元和项目自制 SVG 概念稿组成，不包含外部美术资产。

## 可访问性检查

- 文档语言为 `zh-CN`；标题、区域、目录、对话框、输入和关键状态具有语义名称。
- 键盘焦点使用 2px 暖金轮廓。目录和命令/月末对话框已有焦点约束；战术攻击与撤退确认会自动聚焦“取消”，`Escape` 可按优先级关闭确认或边缘面板。
- 粗指针环境统一把按钮、选择框、输入、文件入口和折叠摘要提高到至少 44px；915×412 实测底栏按钮高 45px，战术确认按钮实测高 44px。
- 安全区使用 `env(safe-area-inset-*)`，页面和战术外壳使用 `100dvh`；手机竖屏会给出横屏游玩提示，但仍保留降级布局。
- `prefers-contrast: more` 和 `prefers-reduced-motion: reduce` 已有明确 CSS 分支。物理设备的系统放大、屏幕阅读器手势和 Safari 焦点行为仍需真机确认。

## 加载与性能

- Phaser 已从首屏静态依赖改为进入战略地图或手动战斗后动态载入，加载期间显示有语义的进度或错误提示。
- 本轮生产构建主 JS 为 739.99kB（gzip 177.00kB）；Phaser 独立延迟块为 1,481.73kB（gzip 339.85kB），战略/战术入口块分别约 3.55kB 与 4.88kB。改造前单一主块为 2,230.96kB（gzip 520.93kB）。
- 战略和战术画布在五档视口均只创建一个 canvas；切换界面时销毁控制器，重新进入后按最新权威状态创建。
- 战术画布目标 30 FPS；触摸由画布捕获，地图拖动使用移动阈值避免把平移误判为选择。
- 自动化的 48 个月战役浸泡测试继续约束长期规则状态。浏览器长时间内存、低端 Android GPU 和 iOS Safari WebGL 恢复尚未经过物理设备量测。

## 发布前真机清单

1. iPhone Safari 横屏验证刘海/灵动岛安全区、地址栏收缩、全屏切换、系统字体放大和刷新恢复。
2. 中低端 Android Chrome 验证首启 Phaser 下载、画布拖动/点选、软键盘弹出、后台恢复和 30 分钟连续游玩。
3. iPad Safari 与 Android 平板验证分屏、旋转、外接键盘焦点和目录内部滚动。
4. 各至少完成一次新开局、内政命令、出征、月末、手动存取档、手动战斗和刷新恢复，并记录设备、OS、浏览器版本与结果。

物理设备检查属于发布前剩余风险，不应把本记录中的 Chromium 视口模拟表述成真机通过。
