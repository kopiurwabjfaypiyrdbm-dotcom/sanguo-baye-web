# 原版兼容策略

本项目以步步高电子词典版《三国霸业》的规则和体验为基线，但采用现代 Web 重写。兼容工作的目标是让结论可定位、可重复验证，并明确区分“原版语义”“参考移植行为”和“现代化选择”。

## 一致性层级

| 类别 | 要求 | 示例 |
|---|---|---|
| 确定性规则 | 对已取得权威证据的输入，整数宽度、截断点、阈值和结果精确一致 | 攻防属性、兵种克制、固定数据索引 |
| 随机规则 | 保留随机调用位置与顺序、取值区间、取模方式、比较方向和概率边界 | `gam_rand() % 101 < 30` |
| 随机序列 | 正式游戏不要求复现未知的 BBK `SysRand` 逐次输出；已验证的 Web `rand_r` 只作为参考模式 | 差分测试、回归诊断 |
| 现代呈现 | 可以改变布局、分辨率、输入方式、动画和可访问性，但不得静默改变规则结果 | React/Phaser UI、双主题 |
| 有意规则变化 | 必须是显式、可关闭、可版本化的现代规则选项 | 平衡调整、原版缺陷修复 |

兼容声明只覆盖已经进入 `references/parity-matrix.md` 且同时具备源码定位、参考证据和自动化验证的行为。当前临时核心即使测试通过，也不自动获得“原版一致”状态。

## 随机数策略

- `baye-web-reference`：`src/compat/baye/rng.ts` 实现固定 Web/WASM 移植中的 `rand_r`。它用于差分测试和诊断，不代表 BBK 设备 RNG。
- `modern-v1`：正式游戏使用项目自有、确定且可版本化的随机算法。未来存档必须同时保存算法标识和种子，不能只保存一个无语义的整数。
- 原始随机规则的调用点、调用次数和阈值仍属于兼容范围。换言之，可以不复现设备的具体数列，但不能把“30% 检查”改成不同区间、不同边界或不同调用时机。
- 若以后取得可信的 `SysRand` 实现或设备输出序列，可新增设备参考模式和差分样本；该考据不阻塞资源解析、规则还原和现代化呈现。

## 事实源与冲突处理

冲突时按以下顺序裁决：固定版本的可复现实测结果、共享 C 核心源码、技术文档默认算法、项目说明、当前 TypeScript 原型。发现平台或版本差异时保留两个明确命名的兼容分支，不用“自动猜测”把差异隐藏起来。原版 legacy 资源头为 12 字节、变长索引为两个 `U16`；当前移植的 wide 资源头为 14 字节、变长索引为两个 `U32`。

原版 `.lib`、字体、图像和二进制只在被忽略的本地参考区使用。仓库可以提交解析器、字段观察、哈希和最小合成测试，但不提交原始资产或可替代其分发的数据转储。

## 当前推进边界

1. 先建立 `.lib` 容器的安全读取、资源定位和合成夹具。
2. 再用本地原版库验证剧本、城市、人物、队列、名称和战斗表的真实布局。
3. 数据结构转换与规则接线必须建立在上述证据上；当前 C 移植扩宽后的结构不能直接套用到旧版 `dat.lib.orig`。
4. Phaser/React 的现代化呈现与兼容层解耦，通过已解析领域数据交互。
