# MB06 人物任命与装备管理完成报告

日期：2026-08-03
引擎：Godot 4.7.1 stable official `a13da4feb`
语言：GDScript

## 结果

生产 `GameSession` 已支持奖赏人物、现代规则手动任命太守、道具赏赐和卸下装备。四项能力由纯 `RefCounted` 领域模块实现，经显式 application adapter 注册，并通过统一事务边界提交；人物管理场景只消费 query DTO、提交 command intent，不持有规则或直接修改状态。

实现保持 Web 产品的 100 金奖赏成本、忠诚变化与上限、君主特例、经典自动太守拒绝、现代太守持久化、两个有序通用装备位、有效武力/智力/移动加成、三类兵符资格和兵种覆盖、库存转移顺序、日志及失败原子性。四项命令均不推进 seed，也不占用月度行动。

## 确定性与状态证据

共享 application-session fixture 从 37 路扩展到 56 路事务。新增矩阵覆盖奖赏成功、君主拒绝、资金不足、忠诚封顶、经典任命拒绝、现代任命成功、普通装备赏赐/卸下、两槽顺序与满槽拒绝、有效属性门槛、精锐/术士/水军三类兵符、君主与普通人物忠诚差异、错误归属、缺失参数优先级、失败状态不变和跨命令连续序列。

精锐与术士成功样例使用“基础属性未达门槛、装备加成后达标”的人物，证明资格判断读取有效属性；另有未达标拒绝样例。Godot 对每步 result core、receipt、返回 state、before/after canonical SHA-256 及最终状态与 TypeScript oracle 逐项比较，56 路共 589 项断言通过。

查询契约返回稳定 `officerOrder`、有序库存/装备、太守、兵种、忠诚/体力、基础与有效武力/智力/移动、奖赏成本、装备位上限、任命模式及各操作可用性/原因。DTO 是深拷贝，稳定顺序不依赖 `Dictionary` 遍历。

## 原生交互

城池空间卡片提供独立“人物”入口，不挤占七项内政命令。原生人物面板支持前后切换人物、查看君主/太守/兵种/忠诚/体力、对照基础与有效属性、识别装备与剩余槽位，并根据 DTO 显示奖赏、任命、赏赐和卸装入口及不可用原因。

窄屏采用紧凑单层操作布局和大触控目标。最终实机审查将前后人物按钮修正为至少 48px 逻辑尺寸；844×390 下按钮实测物理宽度不低于 47.5px，面板未侵入底部状态区。奖赏使用中文确认反馈，人物切换与操作状态即时刷新。
