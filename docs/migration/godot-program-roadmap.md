# Godot 完整迁移程序路线图

本文件提供人类可读的远期视图。Mission 注册表以 `godot-program-roadmap.json` 为准，当前执行位置只以 `godot-program-state.json` 为准；对话、HANDOFF 和本文件中的状态描述都不能覆盖机器账本。

MB00 是不可由执行者自行改变的总委托，不计入 25 个实施 Mission。MB01–MB25 是当前规划基线，允许在 MB00 约束内根据新证据调整为约 22–28 个单一结果，但调整必须同步机器路线图并留下决策记录。

| 波次 | Mission | 结果边界 | 当前状态 |
|---|---|---|---|
| 总委托 | MB00 | 完整 Godot 原生迁移的最终结果、约束与完成证据 | 固定 |
| 技术证明 | MB01 | Godot 4.7.1 Android 技术样片 | 已完成 |
| 迁移基础 | MB02–MB04 | 确定性验证平台、正式数据契约、正式 GameSession | 已完成 |
| 战略完整 | MB05–MB12 | 城市、人物、外交、情报、事件、生命周期、AI 和完整月循环 | MB05–MB09 已完成；MB10 执行中 |
| 战术完整 | MB13–MB19 | 确定性战斗模拟、地形移动、战斗规则、AI、原生表现和回接 | 规划 |
| 客户端平台 | MB20–MB23 | 正式存档、完整战略/战术 UI、Android/Windows 硬化 | 规划 |
| 程序收口 | MB24–MB25 | 全量 parity/soak 与发布候选证据 | 规划 |

## 推进协议

- 任一时刻只有一个活动实施 Mission；新的 Brief 只能在上一 Mission 证据闭环后即时生成。
- 简报生成与实施是两个逻辑检查点：调用 `$mission-brief` 时只创建一个简报，随后重新读取它再实施。
- 每个 Mission 必须留下完成报告、本地提交、账本更新和可复验证据；失败测试是继续诊断的输入，不是降低门槛的理由。
- 若当前 Mission 被非关键外部条件阻塞，可登记后选择依赖已满足的其他 Mission；若没有安全可执行项，按 MB00 审批边界请求用户。
- `npm run godot:program-check` 是恢复和检查点前置门。它必须能在不了解对话历史的新进程中给出唯一当前 Mission 与下一动作。
